# 中文语音同传

用户要听中文时读取。与字幕共用同一视频的译文，语音实现统一维护在 `assets/chinese-interpretation.js`，无需再建一套字幕提取或翻译流程。

## 当前能力与条件

- 当前实现是**已有完整时间轴和中文译文的录播同步播报**。使用浏览器语音合成，默认优先本机普通话声音；每次加载默认关闭，用户点击开启后才发声。
- 支持语音独立开关、选择声音、播报时可选降低原声；暂停、缓冲、跳转和倍速变化跟随视频，关闭或播报结束时恢复原声音量，用户手动调音量时不强行覆盖。
- 语音不依赖字幕面板是否显示。关闭字幕可继续听中文；关闭语音仍可看字幕。不会自动暂停或拖动视频。
- 长句按标点切分，句内时间按文本长度估算；下一段到点会中断未说完的旧段，避免越积越慢。可能有句尾截断，不能保证无损配音或零延迟。
- 暂不支持边翻译边播报或直播语音。直播字幕翻译仍按主技能运行；无字幕直播的采音、实时识别与语音输出是待另行实现的链路，不能通过加 `--speech` 宣称已支持。

## 复用与生成

先检查目标页面是否已经装有同传脚本，有则优先使用或修复。现成课程脚本仅供其匹配的视频使用，不扩大匹配范围，不给同一页面同时装两套语音或字幕。

为新录播准备主技能相同的 `captions.json`：每条都需要 `start`、`end`、`en`、非空 `zh`，对应实际视频时间。缺少译文时先完成翻译，不拿尚未返回的在线译文当作语音输入。

在技能目录运行：

```bash
python3 scripts/build_userscript.py --data captions.json --match 'https://example.com/watch/lesson-1' --speech --output lesson.user.js
```

多播放器页面经检查后使用 `--video-selector` 指定同一个目标视频。构建器拒绝直播或不完整中文译文与 `--speech` 的组合。省略该参数沿用纯字幕脚本。

维护已有自定义脚本时，只嵌入 `assets/chinese-interpretation.js` 并在其完整译文可用后调用 `installChineseInterpretation(cues, {videoSelector: '实际视频选择器'})`；单视频页面可省略第二个参数。避免重写其原字幕 UI 或改原有定时器。可复用逻辑改在模块源文件，安装包由源文件生成，不把课程字幕放进通用技能仓库。

安装按主技能的篡改猴流程。更新已有脚本须核对名称、命名空间和页面匹配，防止装成并行副本；需要刷新时保存并恢复播放进度。

## 验证与故障定位

1. 默认静音；点击开启且播放视频后，至少核对两句中文与当前内容一致。分别关闭字幕、关闭语音，确认另一功能不受影响。
2. 暂停/继续、拖动到有字幕与空白区、切换倍速；旧句不得排队继续播放。检查降低原声开关、结束与关闭后的音量恢复，以及手动调音量被保留。
3. 无普通话声音时明确显示提示；声音列表可能稍后才加载。选用本机声音时无需在线语音服务，在线声音可能发送文本至其提供方。语音合成接口参考 [SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)。
4. 按钮可见或触发 `onstart` 不代表听到声音。实际听取或用户反馈才能确认真实出声；自动化只能验证状态与事件。没测到声音时如实写“代码检查通过，实际出声未验证”。

语音模块回归：`node --test tests/chinese-interpretation.test.cjs`。测试使用模拟语音，不操作用户正在看的页面。
